# AI 数据聊天页设计规格

日期：2026-05-15  
状态：草案（待用户评审）  

## 目标与范围

### 产品目标

在现有应用的 `AI数据` Tab 中，首版只做一个全屏 AI 聊天窗口，用来验证 FastGPT RAG 的问答体验。页面保持当前产品的白灰色工具风格，不做股票仪表盘、不做比赛数据爬取、不做赔率趋势展示。

### 首版范围

- `AI数据` Tab 展示为全屏聊天页。
- 页面顶部显示标题和连接状态。
- 首屏显示欢迎语和 3 个推荐问题。
- 推荐问题必须包含 `今日推荐`，并作为首个推荐问题。
- 底部固定输入框，支持用户输入并发送问题。
- 后端通过 `/api/ai/chat` 代理 FastGPT。
- FastGPT API 地址与 API key 只放在后端配置中，不进入前端页面或浏览器构建产物。
- AI 回答使用流式输出，降低用户等待感。

### 非目标

- 不做仪表盘、KPI、赔率趋势图或异动榜。
- 不做比赛数据爬取、清洗、缓存或数据中台。
- 不做多会话历史、账号级聊天记录、附件上传或票据自动上下文注入。
- 不做全局悬浮 AI 助手；首版只在 `AI数据` Tab 中使用。

## 页面设计

### 视觉风格

页面延续当前产品的白灰色风格：

- 背景使用浅灰。
- 聊天卡片、推荐问题、AI 气泡使用白色或浅灰。
- 用户气泡和发送按钮使用深灰/黑色作为主强调色。
- 卡片圆角保持克制，约 8-10px。
- 页面整体偏工具型、清爽，不使用深色科技盘视觉。

### 页面结构

从上到下：

1. 顶部栏
   - 标题：`AI数据`
   - 连接状态：`已连接`、`连接中`、`未配置` 或 `不可用`
2. 聊天内容区
   - 首次进入显示欢迎语。
   - 首次进入显示推荐问题。
   - 聊天开始后展示用户消息和 AI 消息。
3. 底部输入区
   - 文本输入框。
   - 发送按钮。
   - 流式回答中显示停止生成入口。

### 推荐问题

首版固定 3 个推荐问题：

- `今日推荐`
- `帮我复盘这张票哪里判断错了`
- `解释一下让球胜平负怎么理解`

点击推荐问题等同于把该文本作为用户消息发送给 AI。

## 前端行为

### 状态模型

前端至少维护：

- `messages`：聊天消息列表，区分 `user` 与 `assistant`。
- `inputValue`：输入框内容。
- `isStreaming`：是否正在接收流式回答。
- `activeRequest`：当前请求控制器，用于停止生成。
- `error`：当前页面级错误或消息级错误。

### 发送流程

1. 用户输入问题或点击推荐问题。
2. 空文本不允许发送。
3. 立即追加用户消息。
4. 立即追加一条 AI 占位消息，显示正在思考。
5. 调用 `/api/ai/chat`。
6. 接收流式 chunk，并持续追加到同一条 AI 消息。
7. 流结束后恢复输入状态。

### 停止生成

流式回答中，用户可以停止生成：

- 前端中断当前请求。
- 保留已经生成的回答。
- AI 消息标记为 `已停止`。
- 输入框恢复可用。

### 错误处理

- API key 未配置：显示 `AI 服务未配置`。
- FastGPT 无响应或超时：显示 `AI 服务暂时不可用，请稍后重试`。
- 流式回答中断：保留已生成内容，并显示 `回答中断，可重试`。
- 用户手动停止：保留已生成内容，并显示 `已停止`。

错误信息不展示 API key、请求头或后端内部异常细节。

## 后端代理设计

### 配置

后端从环境变量或本地配置文件读取：

- `FASTGPT_API_BASE=http://175.27.228.129:4000/api`
- `FASTGPT_API_KEY=<secret>`

配置文件不得被提交到仓库。仓库可提供 `.env.example`，只包含变量名和示例占位值。

### 接口

`POST /api/ai/chat`

请求体：

```json
{
  "messages": [
    { "role": "user", "content": "今日推荐" }
  ]
}
```

响应：

- 首版使用流式响应。
- 推荐格式为 `text/event-stream`，服务端把 FastGPT 的流式输出转换成前端统一 chunk。
- 流结束时发送完成标记。
- 失败时发送错误事件，或以合适 HTTP 状态返回错误 JSON。

### 代理职责

- 校验后端配置是否完整。
- 将前端消息转换为 FastGPT 所需格式。
- 附加 FastGPT API key。
- 设置请求超时。
- 将 FastGPT 的流式响应转换为前端可消费的统一格式。
- 支持前端取消请求。
- 屏蔽敏感信息，禁止在日志中输出 API key。

## 数据与隐私

- 首版不持久化聊天记录。
- 页面刷新后聊天记录可以丢失。
- 前端不得包含 FastGPT API key。
- 后端日志只记录请求结果和错误类别，不记录完整密钥。
- 若后续加入票据上下文，需要在发送前明确哪些票据字段会进入 AI 请求。

## 测试范围

### 前端测试

- 首屏展示欢迎语和 3 个推荐问题。
- 推荐问题中包含且首个为 `今日推荐`。
- 点击推荐问题会发送消息。
- 普通输入可发送，空输入不可发送。
- 流式 chunk 会追加到同一条 AI 消息。
- 流式中可以停止生成。
- 接口失败、超时、中断时有可见提示。

### 后端测试

- 未配置 API key 时返回明确错误。
- 代理请求不会把 key 返回给前端。
- FastGPT 流式响应能被转换为统一前端 chunk。
- 上游失败时返回可读错误。
- 取消请求时后端能终止上游连接或停止继续转发。

### 验证

- 构建产物中搜索不到 `FASTGPT_API_KEY` 的值。
- 浏览器网络请求只访问本项目后端，不直接访问 FastGPT 地址。
- 页面在移动端宽度下输入框和气泡不溢出。

## 后续扩展

首版稳定后再考虑：

- 多会话历史。
- 票据详情页带上下文发起 AI 复盘。
- `今日推荐` 接入真实赛程、赔率或爬虫摘要。
- 全局悬浮 AI 助手。
- 流式 Markdown 渲染、引用来源展示和回答复制。
